# v1.20.0 · 서버 없는 기록 보관과 복원

이 문서는 v1.20 도입 기록입니다. v1.21부터는 [지정한 파일 하나의 자동 갱신·실행 시 불러오기](local-records-1.21.md)를 추가했습니다.

2026년 11월 20일. 별도 계정·데이터 서버·클라우드 전송 없이, 기존 기기 기록을 보호하고 파일로 옮길 수 있도록 추가했습니다. 학습 콘텐츠와 보상 규칙은 v1.19.0과 같습니다.

공개 앱: [French Alone](https://sidebatch.github.io/french-alone/) · [v1.20.0 배포 성공](https://github.com/sidebatch/french-alone/actions/runs/44783008366) · 앱 소스 [12b595c](https://github.com/sidebatch/french-alone/commit/12b595c48a27a2b6f2d77a888f3b8c767ca0acba)

## 사용 방법

설정의 **기록 확인·백업**에서 학습일·XP·스탬프 잔액·구매 아이템·이어하기와 저장 상태를 확인합니다.

1. **백업 파일 저장**을 누르고 기기의 다운로드 목록에서 JSON 파일을 확인합니다. 브라우저 저장 공간과 별도로 파일을 보관합니다.
2. **파일에서 불러오기**로 이전 파일을 고릅니다. 선택만으로는 현재 기록을 바꾸지 않습니다.
3. 날짜와 학습량을 확인한 뒤 **이 기록으로 복원**을 누릅니다. 기록은 합산하지 않고 교체하며, 교체 전 원본은 별도 보관합니다.
4. 앱을 다시 열면 복원한 진도·스탬프·구매·방 배치·문법 열람·진행 중인 답안을 이어갑니다. 이 과정은 오프라인에서도 동작합니다.

자동 보관본도 **확인 → 이 기록으로 복원** 순서로 사용합니다. **저장 상태 자세히 → 확인 내용 복사**는 앱 버전, 실행 주소, 브라우저, 항목별 읽기 상태, 집계 수와 보관본 유무를 텍스트로 복사합니다. 원본 답안 전체를 복사하거나 전송하지 않습니다.

## 원본 보호

- 기존 다섯 저장 키를 그대로 사용합니다. 전체 원본을 먼저 읽고 나서 기존 진도 읽기·화면 렌더링을 시작합니다.
- 읽기 실패, JSON 손상, 지원하지 않는 버전, 잘못된 주요 필드 형식을 감지하면 쓰기를 멈춥니다. 기본값으로 읽힌 빈 진도가 원본을 덮어쓰지 못하게 하고, 홈에 **기록 확인·백업** 바로가기를 표시합니다.
- 쓰기 직전 다섯 키를 마지막으로 읽은 값과 비교합니다. 다른 창의 새 기록을 오래된 상태로 덮어쓰려 하면 저장을 멈추고 다시 열도록 안내합니다. 여러 창 사이의 완전한 데이터베이스 트랜잭션이나 자동 병합은 아닙니다.
- 손상된 원본도 읽을 수 있다면 문자열 그대로 파일로 보관합니다. 손상된 파일의 바로 복원은 거절합니다. 읽기 자체가 실패한 항목이 있으면 불완전한 파일을 정상 백업처럼 만들지 않습니다.
- 새 복원은 현재 원본 다섯 항목을 먼저 보관해야 시작합니다. 저장 도중 실패하면 이전 항목으로 되돌리고, 되돌리기도 실패하거나 앱이 중단되면 복원 전 보관본을 남겨 다음 실행에서 쓰기를 보호합니다.

## 기기 안 자동 보관

| 저장 키 | 내용 |
| --- | --- |
| `bonjour-snapshots-v1` | 최근 기록 한 벌과 날짜별 첫 기록 최대 3벌. 각 벌에는 기존 다섯 키의 원문과 시각을 함께 보관 |
| `bonjour-recovery-v1` | 파일·자동 보관본 복원 직전의 원문, 복원 진행 상태와 의도적으로 비운 항목 |

앱을 열 때 읽을 수 있는 기존 기록을 먼저 보관합니다. 정상 저장 뒤 잠시 입력이 멈추거나 화면을 떠날 때 여러 항목을 함께 보관합니다. 빈 기본값이나 읽기 실패로 정상 보관본을 갱신하지 않습니다. 같은 내용인 보관본은 목록에서 합쳐 표시합니다.

공간이 부족하면 자동 보관 개수를 줄입니다. 자동 보관이 활성 기록의 저장을 막는 경우 기존 자동 보관본 한 벌을 남기고 활성 기록 저장을 재시도합니다. 복원 직전 원본은 이 과정에서 삭제하지 않습니다. 자동 보관이 불가능해도 기존 원본 저장을 계속할 수 있으면 유지하고, 파일 저장을 안내합니다.

전체 초기화 확인에는 기기 보관본도 함께 삭제된다고 안내합니다. 원본 보호 중에는 초기화를 막고 먼저 기록을 확인하도록 합니다. 다운로드한 파일은 앱 초기화로 삭제하지 않습니다.

## 한계와 기록 유실 신고

자동 보관본은 원본과 같은 브라우저 저장 공간에 있습니다. 브라우저의 사이트 데이터를 전부 지우면 원본과 보관본이 모두 없어질 수 있습니다. **앱 밖에 저장한 백업 파일**이 별도로 필요합니다. 다른 기기로 자동 동기화하지 않으며, 운영체제 파일 선택 화면을 통해 사용자가 파일을 옮깁니다.

지원 브라우저에서는 **기기 저장 보호 요청**으로 자동 정리 대상에서 제외해 달라고 요청할 수 있습니다. 허용 여부는 브라우저가 결정하며, 사용자가 직접 삭제하는 것까지 막지는 못합니다. [MDN: persist()](https://developer.mozilla.org/en-US/docs/Web/API/StorageManager/persist), [브라우저 저장 한도와 정리](https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria)

동일 Android 기기·동일 설치 앱에서 진도·스탬프·구매가 모두 사라졌다는 신고가 출발점입니다. 해당 실기기의 저장 공간에는 직접 접근하지 못했으므로 **실제 유실 원인이나 복구 여부는 확인되지 않았습니다**. 별도의 Chrome 환경에서는 v1.18.0에서 v1.19.0으로 업데이트하면서 다섯 저장 키가 원문 그대로 유지되는 것을 확인했습니다. 이 결과가 실기기의 유실 원인을 배제하는 것은 아닙니다.

v1.19.0에는 자동 보관·파일 백업 기능이 없었습니다. v1.20.0 설치가 그 전에 사라진 기록을 재생성하지는 않습니다. 현재 원본·자동 보관본·사용자가 따로 가진 파일 중 남아 있는 자료로만 복원합니다.

## 검증

- 구문 검사 36개와 전체 자동 테스트 168개를 통과했습니다. 이 중 저장·복원 전용 테스트는 26개입니다.
- 저장·복원 전용 테스트: 읽기 실패, 손상 JSON, 이전·향후 버전, 다른 창의 변경, 공간 부족, 불완전·다른 앱 파일 거절, 복원 전 원본 저장, 부분 실패의 되돌리기와 복원 중단 보호.
- 화면 테스트: 확인과 진단 복사의 읽기 전용 동작, 파일 선택 후 미리보기·취소·확정, 파일을 읽는 중 화면을 떠났을 때 처리, 손상 기록의 홈 안내와 초기화 방지.
- 실제 Chrome: 390×844와 320×640 화면. 학습 3일·30문항·240 XP·스탬프 잔액 5개·구매 1개와 진행 중인 문제를 파일로 저장한 뒤 테스트 기기 기록을 초기화하고, 오프라인에서 가져와 다섯 키의 원문이 모두 같은지 확인. 손상 원본의 파일 보관, 가로 넘침과 실행 오류 없음도 확인.
- 같은 Chrome 주소에서 실제 v1.19.0 앱·서비스 워커를 먼저 실행하고 **새로 열기**로 v1.20.0으로 업데이트했습니다. 기존 다섯 키와 첫 자동 보관본이 이전 원문과 정확히 같고, 업데이트 후 오프라인 백업 화면이 열리는지 확인했습니다.
- 공개 앱 주소에서도 v1.20.0과 새 백업 자산 3개의 오프라인 캐시를 확인하고, 네트워크를 끈 채 테스트 파일의 다섯 저장 항목을 복원했습니다. 기록을 외부로 전송하는 요청과 실행 오류는 없었습니다.
- 실제 Android 설치 앱에서 파일 다운로드·선택과 유실 신고의 남은 기록 확인은 후속 확인 대상입니다. 테스트용 브라우저의 기록 복원을 사용자의 실제 기록 복구로 간주하지 않습니다.
