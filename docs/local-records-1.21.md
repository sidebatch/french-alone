# v1.21.0 · 파일 하나로 자동 백업

2026년 11월 21일. 서버·계정 없이 사용자가 지정한 JSON 파일 하나를 자동으로 갱신하고, 앱을 켤 때 먼저 확인합니다. v1.20의 기기 보관본·원본 보호·직접 파일 저장과 복원도 유지합니다.

공개 앱: [French Alone](https://sidebatch.github.io/french-alone/) · [v1.21.0 배포 성공](https://github.com/sidebatch/french-alone/actions/runs/44872104541) · 앱 소스 [b2b856b](https://github.com/sidebatch/french-alone/commit/b2b856ba4d5f1c3602e8263aa45203c472958243)

## 처음 한 번 연결

**같은 설치 앱 → 설정 → 기록 확인·백업 → 자동 백업 파일 지정**에서 기기의 다운로드 또는 문서 폴더를 선택합니다. 기본 이름은 `french-alone-backup.json`입니다. 기록을 확인한 뒤 **이 파일로 자동 백업 시작**을 누르고 파일 접근을 허용합니다.

이미 가진 파일은 **기존 파일 연결**로 선택합니다. 파일과 기기 기록을 비교한 뒤 **파일 기록으로 시작** 또는 **현재 기록으로 시작**을 고릅니다. 파일 선택만으로 덮어쓰거나 진도를 바꾸지 않습니다.

연결 뒤에는 직접 다운로드할 필요 없이 같은 파일을 계속 갱신합니다. 자동 백업은 이름에 `(1)`, `(2)`를 붙인 파일을 매번 만들지 않습니다. 사용자가 이미 보관한 다른 파일은 삭제하지 않습니다. 별도로 펼치는 **파일을 직접 저장·불러오기**는 누를 때마다 수동 파일을 내려받는 기존 기능입니다.

## 저장과 실행 순서

1. 학습·설정·구매·초안의 변경을 기존 기기 저장 공간에 먼저 기록하고 읽어 확인합니다.
2. 짧은 연속 변경을 모아 지정한 파일에 기록합니다. 저장이 끝난 파일을 다시 읽어 확인한 뒤 **파일에 저장됨**, 홈에서는 **기기·파일 저장됨**으로 표시합니다.
3. 앱을 열면 화면의 학습 상태를 만들기 전에 연결한 파일과 기기에 남은 기록을 읽습니다. 기기 원본이 없거나 읽을 수 있는 형식이 아니면 정상 파일에서 복원합니다. 복원 직전 원문은 기기에 남깁니다.
4. 직전 종료 때 파일 갱신이 끝나지 않아 기기에 더 최신 기록이 남았다면 그 기록을 유지하고 파일을 갱신합니다. 파일과 기기가 각각 바뀌었거나 오래된 파일로 교체됐다면 자동 덮어쓰기를 멈추고 선택을 요청합니다.

파일에는 현재 기록과 **직전 정상 기록 한 벌**을 함께 담습니다. 이전 기록 안에 이전 기록을 계속 중첩하지 않습니다. 쓰기 실패·파일 삭제·권한 해제·다른 창의 동시 접근은 성공으로 표시하지 않으며, 기기 원본을 유지합니다. 파일을 다시 쓰기 직전에도 내용이 외부에서 바뀌지 않았는지 확인합니다.

기존 수동 복원 또는 전체 초기화를 선택하면 자동 파일 연결을 해제해 다음 실행에서 옛 파일이 선택한 기록을 되돌리지 않도록 합니다. 외부 파일 자체는 지우지 않으므로 필요하면 다시 연결할 수 있습니다.

## 저장 위치와 형식

- 기존 다섯 원본 키와 v1.20의 두 보관 키는 변경하지 않습니다.
- IndexedDB `french-alone-file-backup-v1`의 `connection` 저장소에 선택한 파일 핸들, 마지막으로 확인한 원문·저장 시각과 연결 상태를 보관합니다. 데이터 서버에 전송하지 않습니다.
- 외부 파일은 기존 `french-alone-backup`, 버전 1 형식을 유지하고 선택적 `previous` 항목을 추가합니다. v1.20의 파일과 호환되며 현재 기록은 기존 수동 불러오기로도 읽을 수 있습니다.
- Web Locks와 파일 쓰기 잠금으로 같은 앱의 여러 창이 파일을 동시에 교체하지 않도록 합니다. JSON 파일은 최대 5MB로 검증합니다.

## 지원과 한계

Chrome 공식 안내에 따르면 File System Access의 파일 선택·읽기·쓰기 기능은 Android Chrome 132부터 제공됩니다. 앱에서는 브라우저 이름이나 버전을 추정하지 않고 실제 파일 선택 API·IndexedDB·Web Locks 지원 여부를 검사합니다. 지원하지 않는 브라우저에는 수동 백업을 안내합니다. [Android 지원 안내](https://developer.chrome.com/blog/new-in-chrome-video-q1-2025), [파일 API](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)

처음 파일 지정과 접근 허용은 사용자가 해야 합니다. 권한이 유지되면 다음 실행에서 자동으로 읽습니다. 권한이 풀렸다면 **파일 연결 다시 확인**으로 다시 허용해야 합니다. 설치 앱의 권한 지속 동작과 일반 탭의 재허용은 브라우저 정책에 따릅니다. [Chrome 파일 접근 권한](https://developer.chrome.com/blog/persistent-permissions-for-the-file-system-access-api)

브라우저 데이터를 전부 삭제하면 연결 정보도 없어질 수 있습니다. 별도로 저장한 파일이 남아 있다면 **기존 파일 연결**로 한 번 다시 선택합니다. 파일을 삭제·이동하거나 기기를 분실한 경우까지 보장하는 백업은 아닙니다. 앱 강제 종료 순간의 아직 끝나지 않은 파일 저장도 보장하지 않으며, 기기에 남은 최신 변경은 다음 실행에서 이어서 반영합니다.

기존 Android 기록 유실의 실기기 원인은 아직 확인되지 않았습니다. 새 기능이 이미 없어진 과거 기록을 재생성하는 것은 아닙니다.

## 검증

- 자동 파일 백업 전용 19개 테스트: 한 파일의 반복 갱신, 원본 유실 뒤 실행 시 복원, 저장 중단과 최신 기기 기록, 파일 변경 충돌, 오래된 파일의 진도 되돌림 방지, 권한·쓰기·연결 정보 저장 실패, 선택 취소와 연결 해제.
- 전체 187개 자동 테스트와 구문 검사 37개로 기존 학습·꾸미기·수동 백업을 함께 확인합니다.
- Chrome 390×844·320×640에서 실제 파일 핸들·`createWritable`·IndexedDB 핸들 보관·Web Locks를 사용했습니다. 파일 하나의 반복 갱신, 기기 원본 다섯 항목 삭제 후 오프라인 자동 복원, 권한 재연결, 최신 로컬 변경 유지, 수동 복원 시 연결 해제와 기존 파일 재연결을 확인했습니다. 가로 넘침과 실행 오류가 없었습니다.
- 같은 주소에서 v1.20.0 앱·서비스 워커를 먼저 실행하고 **새로 열기**로 v1.21.0으로 업데이트했습니다. 다섯 원본 항목이 그대로 유지되고 오프라인에서 새 백업 화면이 열리는지 확인했습니다.
- 공개 앱 주소에서도 위의 한 파일 갱신·오프라인 자동 복원·권한 재연결·수동 복원 호환·기존 파일 연결 흐름을 확인했습니다. 공개 설치 자산 검사도 통과했습니다.
- 자동화에서는 운영체제 파일 선택창을 테스트용 선택기로 대신하고, 브라우저 내부 테스트 파일 핸들을 사용했습니다. 따라서 실제 Android 다운로드 폴더의 선택창·권한 지속과 앱을 완전히 종료한 뒤의 동작까지 실기기에서 확인한 것은 아닙니다.
